## 1. 对比

| 操作/性质 | 顺序表 | 单链表 |
|---|---|---|
| 内存布局 | 连续 | 可离散 |
| 按下标访问 | `O(1)` | `O(n)` |
| 按值查找 | `O(n)` | `O(n)` |
| 已知位置插入/删除 | 通常 `O(n)` | 已知前驱时 `O(1)` |
| 额外空间 | 可能预留容量 | 每结点保存指针 |
| 缓存友好性 | 较好 | 较差 |
| 容量变化 | 可能扩容搬移 | 按结点动态增长 |

## 2. 选择思路

```text
需要频繁按下标访问？
├── 是：优先顺序表
└── 否
    ├── 已知位置且频繁插入/删除：考虑链表
    └── 规模稳定、实现简单优先：考虑顺序表
```

不要只看某一次操作的复杂度，还要考虑：

- 查找目标位置的成本；
- 内存局部性；
- 动态内存管理成本；
- 最大规模是否已知；
- 接口是否需要随机访问。

## 3. 静态链表补充

静态链表用数组下标模拟指针：

```text
index     0        1        2        3
data      A        C       空闲      B
next      3       -1        ·        1

逻辑顺序：0(A) → 3(B) → 1(C) → -1
```

它逻辑上是链表，物理上存放在数组中。
